# MLS KeeperIQ

Context-adjusted evaluation of Major League Soccer goalkeepers.

**Core question:** which MLS goalkeepers provide the greatest complete on-field value when we evaluate shot-stopping, handling, claiming, sweeping, passing, and fielding — rather than judging them primarily by goals allowed?

KeeperIQ is a production Next.js application backed by a Python data pipeline. The site reads static JSON generated by the pipeline, so deployment does not depend on a permanently running Python server. Analytical work also writes a **DuckDB** relational database, an **R** Quarto/R Markdown report, and a responsible **HTML scraper** for public roster metadata — matching the R / SQL / scraping stack common in club analytics roles.

## Why goals allowed misleads

Goals allowed and raw save percentage are dominated by the chance quality a defence concedes. A goalkeeper behind a leaky midfield can post a poor goals-allowed rank while still making above-average interventions; a goalkeeper behind an elite defence can look excellent on traditional metrics while adding little beyond replacement.

American Soccer Analysis publishes goalkeeper Goals Added components in a common goal-equivalent unit. KeeperIQ uses that additivity — it does **not** invent arbitrary weights such as “40% shot-stopping, 20% passing”.

## Features

1. **2025 Final** — stable completed-season evaluation
2. **2026 Live** — continuously updated current-season evaluation with rank movement
3. **Current Talent** — Bayesian blend of 2025 prior evidence and 2026 live evidence
4. Full goalkeeper profiles with component radar/bars, timelines, and deterministic strengths/concerns
5. **Scouting decision tool** — define a recruitment brief (component floors, age, minutes, reliability, archetype, similarity) and shortlist matching keepers with explanations
6. Multi-player comparison with shareable URL parameters
7. **Office exports** — from Scouting and Compare, download Excel workbooks, PowerPoint scouting briefs, and a Word recruitment memo; Leaderboard has a lighter Export Excel action
8. Involvement-based playing-style archetypes
9. About & Methodology landing page with season coverage on Overview
10. Daily GitHub Actions refresh during the MLS season

## Data source

Primary source: [American Soccer Analysis](https://www.americansocceranalysis.com/) public API

- `goalkeepers/goals-added` (season and `split_by_games=true`)
- `goalkeepers/xgoals` (season and `split_by_games=true`)
- `games`, `players`, `teams`

Raw field names are preserved in `data/raw/asa/`. The transform stage maps them into a documented canonical schema and fails loudly if required fields disappear.

## Analytical model (summary)

### Additive total

```
Observed Total G+ =
  Shot Stopping + Handling + Claiming + Sweeping + Passing + Fielding
```

Rates use a **96-minute** basis, matching ASA’s published Goals Added convention.

### Reliability adjustment

Per-opportunity empirical Bayes:

```
adjusted = league_mean + n/(n+k) × (observed − league_mean)
```

`k` is estimated from match-level sampling variance and between-goalkeeper talent variance over 2021–2025 when identifiable. Workload (opportunities per 96) is separately shrunk with a minutes-based constant. Fallback constants live in `pipeline/config/keeperiq.yml` and are labelled as such in generated metadata.

### KeeperIQ score

Minutes-weighted percentile of reliability-adjusted total G+/96 within the qualified + provisional pool. **50 ≈ league median.** It is a percentile score, not a physical unit. Observed and adjusted ranks are both retained.

### Current talent

Normal-normal combination of:

1. league prior (`1/τ²`)
2. 2025 evidence, discounted by year-over-year drift
3. 2026 live evidence

New MLS goalkeepers begin from the league prior; they are not penalised for missing 2025 history.

### Qualification

| Label | 2025 Final | 2026 Live |
| --- | --- | --- |
| Qualified | ≥ 900 minutes | ≥ max(50% of busiest GK minutes, 270) |
| Provisional | ≥ 360 minutes | ≥ max(20% of busiest GK minutes, 90) |
| Limited Sample | below provisional | below provisional |

Default leaderboards show Qualified + Provisional; Limited Sample is available via toggle. Shrinkage always applies.

## Local setup

Requirements: Node 22+, Python 3.11+, npm.

```bash
# Frontend
npm install

# Python pipeline
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
pip install -e .

# Fetch ASA data and rebuild public/data
npm run pipeline

# Develop the site
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

### Offline rebuild

Once `data/raw/asa/` has been populated:

```bash
npm run pipeline:offline
```

### DuckDB, scraping, and R

```bash
# Relational DB is written automatically by the pipeline
# Inspect: duckdb data/keeperiq.duckdb
# SQL sources: pipeline/sql/{schema,views,data_quality,scouting_queries}.sql

# Responsible Wikipedia roster scrape (robots + rate limits + fixtures)
npm run pipeline:scrape

# R statistical report (requires R packages; see analysis-r/README.md)
Rscript analysis-r/install_packages.R
npm run analysis:r
# → analysis-r/output/keeperiq-analysis.html
```

## Deployment

### Vercel

1. Push this repository to GitHub.
2. Import the repo in Vercel (Framework Preset: Next.js).
3. Build command: `npm run build`. Output: default Next.js.
4. No environment secrets are required for the public ASA endpoints.
5. Enable the GitHub Actions workflow so `public/data/` stays current; Vercel will redeploy on those commits.

### GitHub Actions

`.github/workflows/update-data.yml`:

1. Runs daily at 14:15 UTC and on manual dispatch
2. Installs Python + Node dependencies
3. Fetches ASA data with `--force`
4. Validates, rebuilds artefacts, runs pipeline + frontend tests and a production build
5. Commits changed `public/data`, `data/processed`, and `data/snapshots` (no `[skip ci]`, so Vercel can redeploy the live site)

The site surfaces last attempted update, last successful update, latest match date, and whether the displayed data is current or a fallback on **Overview → Season coverage**.

## Limitations

- Team tactical context and defensive-line height change opportunity mixes.
- Passing G+ also depends on receivers.
- Goals Added is a model estimate, not objective truth.
- Small samples remain noisy even after shrinkage.
- Players entering MLS begin at a league-average prior until local evidence accumulates.
- KeeperIQ is a percentile of estimated impact, not a projection of future transfer value.

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| Empty leaderboard | Run `npm run pipeline` to generate `public/data`. |
| `SchemaError` on refresh | ASA renamed a field; check the error detail and update `pipeline/config/keeperiq.yml` / `schema.py`. |
| Offline mode fails | Seed the cache once with a networked `npm run pipeline`. |
| Rank movement blank | Needs at least two snapshots in `data/snapshots/season-2026/`. |
| Python import errors | `pip install -e .` and ensure `PYTHONPATH=pipeline/src` or the console script `keeperiq`. |
| DuckDB missing | Run `npm run pipeline:offline` (DB is rebuilt with JSON). |
| R report fails | Install packages with `Rscript analysis-r/install_packages.R` (DuckDB R may compile from source). |
| Scrape blocked | Check `docs/SCRAPING.md`; fixture tests still cover parsing offline. |
